# BUG-11 — Stale `*.feature.cs` files sit in the source tree

| | |
| --- | --- |
| Severity | Low |
| Area | Build, hygiene |
| Location | `test/uk.osric.asp.Specs/Features/Compiler.feature.cs`, `test/uk.osric.asp.Specs/Features/Greeting.feature.cs` |

## Problem

Two generated code-behind files are present on disk:

- `Compiler.feature.cs` — regenerated by an old Reqnroll generator, but Reqnroll 3 uses a source
  generator, so it is not needed.
- `Greeting.feature.cs` — an orphan: `Greeting.feature` no longer exists, and no step definitions
  match it.

Both are ignored by git (`*.feature.cs`), so they are invisible in review but are still matched by
the SDK's default `Compile` glob and by `dotnet msbuild -getItem:Compile`. I moved them out and ran
the suite: it still passes with the same two scenarios, which confirms they are dead. They also slow
the build and confuse tools that enumerate source files.

## Fix outline

1. Delete both files; do not commit them.
2. Add a `.gitignore`/REUSE note only if the generator ever produces them again (it does not).
3. Consider adding `**/*.feature.cs` to an explicit `<Compile Remove>` in `Directory.Build.targets`
   for defence in depth, or leave the SDK default now that the files are gone.
4. Keep the Makefile's `-not -name '*.feature.cs'` exclusion only if it is still needed.
